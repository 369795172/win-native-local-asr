### 2026-09-17 — app state machine port (Task 6)

- `feat(state): port app state machine from swift`: `src/WinLocalASR.Core/State/AppController.cs` ports `AppState.swift` (all 470 lines read; behavioral SSOT) as pure logic — zero WinForms, zero real timers. Every Swift phase, operation, feedback window and bug-for-bug quirk has a corresponding C# surface.
- **Phase & HUD**: `AppPhase` is a sealed record hierarchy (`Loading/Idle/Recording/Processing/Error(string)` — Swift's payload-carrying enum, structural equality, cached singletons). `DictationHudPresentation` ports the resolve (AppState.swift 20-76) with the exact `hidden/recording/processing/copied/cancelled/error` ControlValue strings Task 12's ControlServer asserts; clipboard failure renders as `error(clipboardCopyFailed)` — no separate `failed` value (upstream parity). `HudText.FormatHudDuration` is the `mm:ss` helper.
- **Seams**: `ITimer` (one-shot Schedule→IDisposable; the 0.1 s recording timer re-arms itself exactly like Swift's invalidate-then-schedule), `IDispatcher` (stands in for @MainActor — async continuations, timer callbacks and audio callbacks all marshal through it), `IClock` (ProcessingStartedAt/ProcessingDuration), plus narrow consumed-service interfaces (`IAudioCaptureService`, `ITranscriptionService`, `IClipboardService`, `ISettingsProvider`) with thin adapters in `Core/State/ServiceAdapters.cs` — the Task 3/4/5 modules themselves are untouched. BCL-only defaults provided: `SystemClock`, `SystemSchedulingTimer`, `SynchronizationContextDispatcher`.
- **Operations (Swift API parity)**: `ToggleRecording` (idle→record, recording→stop+transcribe, everything else ignored — the double-toggle race guard from Swift lines 358-365), `CancelActiveRecording` (Recording-only; syncs cancel-hotkey availability), `StopAndTranscribeAsync` (audio stop → WAV → transcribe with the Swift timeout formula wired via `TranscriptionTimeout.Compute(recordingDuration)` as the explicit `TranscribeAsync` override → clipboard → feedback → temp WAV deleted in every outcome), `RestartBridge`, `ApplySettingsWithoutReload` (limit clamp + device, empty deviceId → null, Esc re-sync), `CopyLastTranscript`, `ShutdownAsync` (phase deliberately unchanged, pending feedback frozen — Swift behavior), `InitializeAsync` (explicit, not auto-run from the ctor — shell controls startup; documented deviation, Task 10 wires it). `runSetup` deliberately deferred to Task 10.
- **Event surface (inter-module contract for Tasks 7/8/9/12)**: `PhaseChanged` (dedup'd — ControlServer phaseHistory), `HudPresentationChanged` (controlValue stream, mirrors the Swift HUD's CombineLatest3+removeDuplicates), `CancelHotkeyAvailabilityChanged` (Esc registration lifecycle), `LastTranscriptChanged`, `RecordingDurationChanged` (0.1 s ticks), `AudioLevelChanged`.
- **Feedback windows via ITimer**: copied 1.5 s, clipboard-failed 3 s, cancel 1.5 s, error 3 s then ready→Idle / not-ready→Error(engineNotReady) with no further loop (bug-for-bug). A newer error/feedback replaces the pending timer (Swift task-cancel semantics); a newer feedback owning the state is guarded at fire time.
- **Error mapping**: `EmptyTranscriptException` (dedicated path when the trimmed transcript is empty), `AudioCaptureException` family and `LlamaServerException` family carry user-facing messages (`UserMessage` switch documents the mapping; never catches a bare `TimeoutException` — the shadowing gotcha).
- Test inventory (61 new in `Tests/State/`): 35 AppController [Fact]s + 26 theory cases, covering every Swift transition (inventory table in the test header mapping AppState.swift lines → tests), including the required set: double-toggle race ignored, empty transcript, error 3 s → Idle, Esc only in Recording, cancel-hotkey sync events, copied 1.5 s auto-hide, max-duration auto-stop, device change via ApplySettingsWithoutReload. QA+ fake-chain e2e (2 s recording → `"你好世界"` → clipboard → Idle → copied → fast-forward 1.5 s → hidden, asserting the full `(phase, controlValue)` event sequence); QA-: RuntimeException → Error → 3 s → Idle, and whitespace transcript → EmptyTranscript.
- Determinism lessons (see test fakes): completed-fake chains run fully synchronously (`ConfigureAwait(false)` everywhere in the controller); but under xunit's AsyncTestSyncContext, completing a pending `TaskCompletionSource` does NOT run continuations inline (a SynchronizationContext current at SetResult time defeats ExecuteSynchronously — verified with a standalone probe) — pending-task tests settle via condition spin instead of assuming synchronous completion. `System.Threading.ITimer` (new in .NET 10) ambiguates the `ITimer` name outside `WinLocalASR.Core.State` — test files need `using ITimer = WinLocalASR.Core.State.ITimer;`.

### 2026-09-17 — settings store, clipboard writer, version manifest (Task 5)

- `feat(core): settings, clipboard, version manifest`: three Core modules landing the persistence/output/pinning surfaces Tasks 10/11/13 build on.
- **Settings** (`src/WinLocalASR.Core/Settings/`): `AppSettings` record (hotkey default `Ctrl+Shift+Space`, nullable deviceId/contextPrompt, recordingLimitSeconds default 120 clamped to [10, 120] on both save and load — the #21847 guardrail, autoStart, configured) + `SettingsStore` persisting JSON at `%APPDATA%\WinLocalASR\settings.json` with an injectable base directory (tests never touch real system paths). Writes are atomic (tmp + move); a corrupt file on load yields defaults, preserves the corrupt bytes as `settings.json.bak`, and rewrites the main file clean.
- **Autostart SSOT split**: `settings.json` is the SSOT (`AppSettings.AutoStart`); the HKCU Run key is derived. `AutoStartHelper.Apply/IsEnabled` writes/deletes `HKCU\…\CurrentVersion\Run` value `WinLocalASR` behind `IRegistryKey`/`IRegistryKeyFactory` (real `RegistryKeyFactory` Windows-only, throws off-Windows; unit tests use an in-memory fake — zero real registry writes). Installer bridge: `SettingsStore.MergePendingAutoStartFlag(factory)` — if `autostart-pending.flag` exists in the settings dir, read current settings, set AutoStart from Run-key presence, read-modify-write settings.json, delete the flag; flag absent = strict no-op. Fake-tested across the flag×runkey matrix. The installer (Task 13) never edits settings.json; this merge is the only path in.
- **Clipboard** (`src/WinLocalASR.Core/Output/`): `ClipboardWriter.SetText` with 3 attempts × 50 ms retry (injectable delay keeps tests instant) over `IClipboardInterop`; the real `Win32ClipboardInterop` is user32/kernel32 P/Invoke (`CF_UNICODETEXT`, no WinForms dependency in Core), single-shot per call — retry policy lives in the writer. `TryGetText` exists for round-trip verification. One Windows-only SkippableFact smoke self-skips when the clipboard is unavailable in headless sessions (full real-clipboard verification is a real-machine item).
- **Versions manifest** (`src/WinLocalASR.Core/Versions/VersionManifest.cs` + repo-root `versions.json`): strongly-typed reader (`llamaCpp{tag,assetName,sha256?,sha256Policy}`, `models{main,mmproj}{repo,file,revision,sha256,sizeBytes}`, `urls{huggingface,hfMirror,github,ghProxyPrefix}`), unknown keys ignored. Template deliberately omits the three resolved-path keys (`llamaServerPath`/`mainModelPath`/`mmprojModelPath`) that Task 4's `LlamaServerPaths` requires — setup (Task 10) writes them into the installed copy; a unit test proves template+keys loads through BOTH readers and that the raw template (correctly) rejects the engine-path reader.
- **llama.cpp pin researched and frozen**: tag `b10964` (same build number the spike validated), asset `llama-b10964-bin-win-cpu-x64.zip`, confirmed by download to contain `llama-server.exe` + the full DLL set (recorded in §Inference Contract). Hash policy = `official`: GitHub's release-asset digest `917f39c0…c5d7` independently verified byte-exact against a local download — not TOFU. Model pins are the spike-verified Q8_0 pair with exact SHA256s/sizes; mirrors hf-mirror.com + ghproxy.cn (prefix form) recorded.
- Test inventory (30 new): settings roundtrip (all six fields), corruption→defaults+.bak (byte-exact corrupt content asserted), first-ever invalid JSON → defaults, clamp theories on save and load, atomic-write leaves no `.tmp`, merge matrix (flag+runkey / flag-only / no-flag no-op with settings.json bytes unchanged / flag before first-ever save); autostart apply/disable/is-enabled fakes + non-Windows guard; clipboard fails-twice-succeeds-third (exactly 3 attempts, delays [50,50]), all-fail (exactly 3), first-try-success (no delay), Windows real-interop round-trip smoke; manifest exact-pin template load, both-reader compatibility, unknown-key tolerance, TOFU-null representable, missing-key/missing-file errors.

### 2026-09-17 — llama-server inference client (Task 4)

- `feat(inference): llama-server client with restart backoff`: ported the lifecycle semantics of `ASRBridgeClient.swift` (lines 22-246) into `src/WinLocalASR.Core/Inference/`, speaking the spike-verified wire contract (§Inference Contract). Public surface maps 1:1 to Swift: `start(...)` → `StartAsync()` (artifact paths via `LlamaServerClientOptions.Paths` / `LlamaServerPaths`, the minimal versions.json reader with the three resolved-path keys `llamaServerPath`/`mainModelPath`/`mmprojModelPath`, forward-compatible with the Task 5 manifest by ignoring unknown keys), `ready` → `IsReady`, `transcribe(audioURL:context:timeout:)` → `TranscribeAsync(wavPath, context, cancellationToken, timeout)`, `stop()` → `StopAsync()` (POST /shutdown attempt kept for parity even though the endpoint 404s, then kill after the 2 s grace), `diagnosticLines` → `GetDiagnostics()` (50-line ring buffer).
- Wire details per contract: spawn `llama-server -m main.gguf --mmproj mmproj.gguf --host 127.0.0.1 --port P` (`UseShellExecute=false`, `CreateNoWindow=true`), port probed from 18100 upward via TcpListener skipping the ControlServer's 17846; ready-poll `GET /health`; transcribe via multipart `POST /v1/audio/transcriptions` with required `file` part (audio/wav) and the hotword `context` mapped to the optional `prompt` field (`response_format` omitted — `json` is the server default, `text` is a hard 400); response `.text` is stripped of the `language X<asr_text>` artifact prefix by `TranscriptArtifactStripper` (`^language\s+[^<]*<asr_text>`, unmatched text returned unchanged).
- Timeout formula `max(90, 3×duration+20)` s in `TranscriptionTimeout`, duration from `WavDurationParser` (RIFF chunk walk, no NAudio dependency); the Swift `timeout` parameter survives as the optional `timeout` override on `TranscribeAsync`.
- Error taxonomy for Task 6, named 1:1 with Swift `BridgeError`: `NotReadyException`, `ProcessExitedException`, `TimeoutException` (deliberately shadows `System.TimeoutException` inside the namespace — consumers should catch the `LlamaServerException` base, qualify, or add a using-alias), `RuntimeException` (carries `StatusCode` + `BodySummary`), `RestartFailedException`. Swift cases not ported: `requestInProgress` (HTTP removes the single-pipe constraint), `unexpectedResponse` (→ RuntimeException), `modelLoadFailed` (startup failure surfaces as ProcessExited on early exit / Timeout on handshake deadline). One documented deviation: caller `OperationCanceledException` propagates without an engine restart (Swift has no cancellation path).
- Crash auto-restart mirrors Swift's loop: single-flight restart with 1/2/4 s backoff, ≤3 attempts, exhaustion raises the `RestartFailed` event and faults the awaitable `CrashRecovery` task; every transcribe failure terminates and best-effort restarts the engine before rethrowing the original error (Swift's terminate+restart catch).
- Seam design: injectable `HttpMessageHandler` and `IProcessSpawner`/`IManagedProcess`; time knobs (backoff, stop grace, startup timeout, health poll) injectable via options so tests run fast. Real spawn goes through `SystemProcessSpawner` (Process + redirected stdout/stderr + Exited events).
- Test inventory (32 new in `Tests/Inference/`): QA+ fake-HTTP-server (HttpListener) end-to-end — ready handshake → transcribe returns the stripped text while asserting the real multipart body carried the `file` part (byte-exact WAV) + `prompt` field + no `response_format`/`model`, and the spawn `ArgumentList` matches the pinned CLI exactly; QA- ×3 — 500 → `RuntimeException(500, body summary)` (plus Swift-parity restart: spawn count 2, original error rethrown), 5 s server delay vs 1 s client timeout → `TimeoutException` in <4 s, 4 consecutive process exits → `RestartFailedException` after exactly 4 spawns with injectable 30 ms backoff; plus artifact-strip fixtures (verbatim EN/ZH/clean/prefix-only from the rfc), timeout-formula + WAV-duration cases (1/60/120 s), versions-reader forward-compat/missing-key/missing-file, port-prober occupied/reserved-skip, empty-context omits prompt, NotReady, stop-kills-without-restart, diagnostics ring last-50, crash-restart recovery, and a real-process spawner smoke (echo via cmd.exe/`/bin/echo`, runs on CI and macOS).

### 2026-09-17 — audio capture module (Task 3)

- `feat(audio): 24khz mono capture, wav writer, level meter`: ported the capture semantics of `AudioCaptureManager.swift` into `src/WinLocalASR.Core/Audio/`. Public surface maps 1:1 to Swift (`SampleRate` 24000, `OnMaximumDuration`, `OnAudioLevel`, `SelectedDeviceId`, `MaximumDuration` default 60 s, `ListInputDevices`, `StartRecording(deviceId?)`, `StopRecording` → `%TEMP%\WinLocalASR-<guid>.wav`, `CancelRecording`), and `AudioCaptureException` subclasses mirror the six `AudioCaptureError` cases for the later state-machine port.
- Seam design: all device access goes through `IAudioDeviceFactory` (`WindowsAudioDeviceFactory` = MMDeviceEnumerator + WasapiCapture shared mode); format conversion goes through `IPcmResamplerFactory` (`MediaFoundationResamplerFactory` = MediaFoundationResampler over a BufferedWaveProvider, float→int16 done in managed code so MF only resamples PCM16). Same-format input takes an identity path that never builds a resampler. Level formula is the Swift lines 219-227 port in `AudioLevelMeter` ((dB+80)/70 clamped to [0,1]); WAV encoding is the canonical 44-byte RIFF header in `Pcm16WavWriter` — the interchange format consumed by `POST /v1/audio/transcriptions`.

## Lessons learned

- .NET 10 `dotnet new sln` defaults to the new `.slnx` XML format. Pass `--format sln` when the classic solution file is required (CI paths, older tooling, editor support).
- xunit types are not covered by `ImplicitUsings`; test files need an explicit `using Xunit;`.
- Referencing the NAudio metapackage from a project that multi-targets `net10.0-windows` requires `<EnableWindowsTargeting>true</EnableWindowsTargeting>` on non-Windows hosts: `NAudio.Winsows` carries a `Microsoft.WindowsDesktop.App.WindowsForms` FrameworkReference that cross-platform builds cannot resolve otherwise (NETSDK1073).
